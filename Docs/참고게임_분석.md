# 참고 게임 분석 — Batomon Showdown (2026-11-06)

> 구조 파악용. 이름 · 아트 · 문구 · 수치를 그대로 가져오지 않는다. `.pck`(게임 데이터)는 암호화되어 있어 열지 않았다.
> 출처: Steam 상점 페이지(공개), 사용자 PC의 게임 데이터 폴더 `%APPDATA%\Godot\app_userdata\Batomon Showdown`(암호화 안 됨, 사용자 본인 데이터), 사용자 플레이 설명.

## 1. 기술 구성
| 항목 | 값 |
|---|---|
| 엔진 | Godot 4.7 (커스텀 빌드) + GodotSteam |
| 백엔드 | PocketBase (오픈소스 백엔드) — 프로필 · 판 저장(클라우드) · 매칭 |
| 치팅 대책 | CheatDetector(프로세스 목록 검사), 판 저장에 `untrusted` 플래그 |
| 저장 | 판 저장 `run_save.json` + 백업 `.bak`, 저장 순번 `save_seq`, 형식 버전 `save_version` |

## 2. 콘텐츠 규모 (게임 로그 "GameDatabase Loaded")

## 3. 한 판 상태 (run_save.json 필드)
- 진행: `round`, `wins`, `lives`, `lives_lost`, `gold`, `shop_rank`(상점 등급), `free_rerolls`
- 팀: `team` 6칸(3×2, 빈칸은 `{}`), `bench` 4칸(대기석), `overflow`
- 몬스터: `species_id`, `level`, `is_shiny`, `extra_types`(추가 속성), `perm_buffs`(스탯 번호 → 영구 버프 값), `blackboard`(개별 메모: 할인 · 충전 등)
- 선택: `trainer_id`, `trinket_ids`(장신구), `event_history`, `shop_content`, `is_shop_frozen_next_round`
- 난수: `seed` + 용도별 순번 `run_rng_seq` · `shop_roll_seq` · `round_action_seq` + 라운드 소금값 `round_salt` → **용도별 분리 시드 난수**
- 기록: `damage_dealt_total`, `faced_run_ids`(같은 상대 반복 방지), `faced_opponent_mmrs`
- 모드: `is_ranked`, `is_endless_mode`, `is_curated_run`, `set_id`
- 관찰: 저장된 판 `lives 7 + lives_lost 3` → 원작은 목숨 10개로 보임

## 4. 비동기 대전 (opponent_cache)
- 파일 단위: `{ranked|casual}_{세트}_{번호}.json` — 세트 · 모드별 상대 묶음, `etag`로 갱신 여부 확인
- 항목: 점수(mmr), 랭크 등급, `round`, `set_id`, 형식 `version`(26), `won`(그 전투 결과), `team_data`(보드 6칸 + 트레이너 · 장신구 · 상점 등급 · 승수 · 잃은 목숨 · 판 메모)
- 라운드별 분포: 1~16라운드 각 120개, 17~20라운드 각 20개 (한 파일 기준)
- 매칭 로그: "라운드 R의 점수 구간(ranked_band_200 등)에서 후보 5개" → 하나 선택. 초반 1~3라운드는 **개발자가 만든 상대**(curated). 일반 모드는 구간을 넓혀 가며 찾음(casual_lower_mmr → casual_any).
- 즉: 라운드가 끝날 때 그 라운드의 내 팀 스냅샷이 서버에 올라가고, 다른 사람이 같은 라운드에서 그것을 상대로 받는다.

## 5. 전투 규칙 (사용자 설명, 2026-11-06)
- 양쪽은 **팀 공통 체력** 하나를 가진다. 라운드가 오를수록 커진다: 300 → 500 → 800 → … → 1400 …
- 누구를 때리든 상성 · 타겟 구분 없이 **상대 공통 체력이 깎인다.**
- 공통 체력이 먼저 0이 되는 쪽이 그 전투에서 진다.
